# ALIGNMENT - UI Optimization

## 1. 项目上下文分析
- **项目类型**：基于 SDCMS 的企业官网
- **技术栈**：PHP (SDCMS 模板引擎), jQuery, CSS3
- **现有结构**：模板文件位于 `theme/2020/content/page/`，缓存文件位于 `cache/compile/2020/content/page/`
- **业务域**：建材/家居行业（品牌介绍、花色展示、产品特点、授权厂家）

## 2. 原始需求
用户要求对 `brand3.php`（或相关品牌页面）进行三项 UI 优化：
1. **花色类型 (Color Types)**：添加折叠/展开功能。默认显示 2 排，提供“显示更多”按钮，点击后展开全部内容，并可再次收起。
2. **产品特点 (Product Features)**：重新格式化布局。使用 2 列卡片式布局，图片比例调整为 926x350，增加悬停效果和居中的标题。
3. **授权厂家 (Authorized Manufacturers)**：放大该区域。增加 Logo 尺寸、间距和内边距，提升视觉显眼度。

## 3. 边界确认
- **范围**：仅限 `brand3.php` 模板及其关联的样式/脚本。
- **排除**：不涉及后端逻辑修改，仅前端展示优化。
- **验收标准**：
  - 花色区域在初始加载时仅显示 2 排。
  - “显示更多”按钮功能正常，展开后变为“收起更多”。
  - 收起时页面平滑滚动回区域顶部。
  - 产品特点区域布局符合 926x350 比例且为 2 列。
  - 授权厂家 Logo 明显增大。

## 4. 需求理解
- 现有的 `brand3.php` 是目前活跃的模板文件（包含 `cid=52` 和 `classid=35`）。
- 之前的修改可能因为缓存未清理或模板选择错误（修改了 `brand.php`）而未生效。
- 需要确保 JS 逻辑与 HTML 结构严格匹配，特别是选择器名。

## 5. 疑问澄清 (智能决策)
- **疑问 1**：为什么用户反馈“没改到”？
  - **决策**：可能是 SDCMS 编译缓存导致的。必须手动删除 `cache/compile/` 下对应的 `.php` 编译文件。
- **疑问 2**：按钮是否在所有分辨率下都可见？
  - **决策**：需要为按钮设置较高的 `z-index` 并确保其在容器流中位置正确，不被遮挡。
- **疑问 3**：折叠高度如何计算？
  - **决策**：根据现有布局，2 排高度约为 660px（含间距）。使用 CSS `max-height` 实现平滑过渡。
