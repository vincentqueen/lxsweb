# CONSENSUS - UI Optimization

## 1. 明确的需求描述
针对 `brand3.php` 模板进行以下三个模块的 UI 升级：
- **花色类型模块**：实现高度限制（约2排）+ 渐变遮罩 + “显示更多/收起更多”切换逻辑。
- **产品特点模块**：实现 2 列卡片布局，强制图片比例 926:350，增强视觉吸引力。
- **授权厂家模块**：显著放大 Logo 尺寸，增加呼吸感。

## 2. 验收标准 (Acceptance Criteria)
- [ ] **花色展示**：
  - 初始高度固定在 660px 左右。
  - 底部有线性渐变白色遮罩（100px高）。
  - 按钮文字在“显示更多”与“收起更多”之间切换。
  - 收起时，窗口平滑滚动至 `#j_clotys` 锚点上方 100px 处。
- [ ] **产品特点**：
  - 页面呈现 2 列网格布局。
  - 所有图片通过 CSS `aspect-ratio: 926/350` 保持一致。
  - 标题居中，且样式与品牌风格统一。
- [ ] **授权厂家**：
  - Logo 高度由原来的默认大小增加至 60px。
  - Logo 间距（gap）增加至 60px。

## 3. 技术实现方案
- **CSS**：使用 Flexbox 和 Grid 布局；利用 `transition` 实现高度平滑动画；使用 `::after` 伪元素制作遮罩。
- **JS**：使用 jQuery 监听点击事件，切换类名并执行滚动动画。
- **SDCMS 机制**：修改 `.php` 模板文件后，必须物理删除 `cache/compile/2020/content/page/` 目录下的相关缓存文件。

## 4. 技术约束和集成方案
- **性能**：避免大图导致页面卡顿，优先使用 CSS 属性而非 JS 计算高度。
- **兼容性**：确保在主流移动端和 PC 端浏览器表现一致。
- **集成**：代码将直接嵌入 `brand3.php` 的 `<style>` 和 `<script>` 标签内，确保局部生效不影响全局。

## 5. 任务边界限制
- 不修改数据库中的数据。
- 不修改公共 CSS/JS 文件（除非必要），优先采用模板内局部样式。
- 仅针对 `brand3.php` 进行修改。
